# Sentiment Analysis

**AICTE Oasis Infobyte Internship — Data Analytics, Level 1, Task 4**

## Overview

An end-to-end NLP pipeline that classifies airline-related tweets as **Positive**, **Negative**, or
**Neutral**, using classical machine learning (TF-IDF + Multinomial Naive Bayes / Logistic Regression). Every
number in this README was generated by actually running the notebook — none of the results below are
estimated or invented.

## Objective

Build and compare two supervised text classifiers on a genuine three-class sentiment dataset, following the
full workflow: raw text → preprocessing → TF-IDF features → train/test split → model training → evaluation →
error analysis → business insights — with every design decision documented and justified against the actual
data.

## Dataset

**Twitter US Airline Sentiment** (Crowdflower "Data for Everyone" library, tweets scraped February 2015).
14,640 tweets directed at six major US airlines, each manually labelled `positive`, `negative`, or `neutral`
by human annotators.

This dataset was deliberately chosen because it contains **all three required sentiment classes natively** —
no neutral labels were invented to satisfy the task requirement, per the internship instructions.

**Columns used:** `text` (tweet content) and `airline_sentiment` (label). `airline` was kept for real-world
framing context. The remaining 12 columns are annotator/collection metadata not needed for text
classification.

## Data Cleaning

- **Missing values:** none — 0 missing `text`, 0 missing `airline_sentiment`.
- **Duplicates:** 36 fully duplicated raw rows (identical across every column, including `tweet_id`) were
  found and removed. Rows sharing only similar short text from *different* tweets/users (e.g. two different
  people both tweeting "thanks!") were correctly **not** treated as duplicates.
- **Rows removed after text cleaning:** 54 tweets became empty once URLs, @mentions, and stopwords were
  stripped (e.g. `"@united done"`), leaving no usable content for TF-IDF. These were removed and the removal
  documented rather than left silently blank.
- **Final dataset used for modelling:** 14,550 tweets (Negative 9,146 / 62.86% · Neutral 3,056 / 21.00% ·
  Positive 2,348 / 16.14%).

## Text Preprocessing

Applied in order: HTML unescaping → lowercasing → URL removal → @mention removal → hashtag-symbol removal
(word kept) → punctuation/digit removal → tokenisation → stopword removal (scikit-learn's built-in
`ENGLISH_STOP_WORDS`) → stemming (NLTK `PorterStemmer`).

**Note on stopwords/stemming:** scikit-learn's stopword list and NLTK's `PorterStemmer` were used instead of
NLTK's downloadable stopword corpus specifically because they require **no external data download**, keeping
the notebook fully reproducible offline, per the project rule that the notebook must run start-to-finish
without breaking.

## TF-IDF Feature Extraction

`TfidfVectorizer(max_features=5000, ngram_range=(1,2), min_df=2, max_df=0.9)`, **fit on training text only**
and then used to transform the test text — no test-set information leaks into the vocabulary or weighting.

## Machine Learning Models

- **Multinomial Naive Bayes**
- **Logistic Regression** (`max_iter=1000`)

Both trained on identical TF-IDF training features and evaluated on an identical, stratified 80/20 test
split (`random_state=42`): 11,640 training tweets / 2,910 test tweets.

## Model Evaluation

| Model | Accuracy | Precision (weighted) | Recall (weighted) | F1-Score (weighted) |
|---|---|---|---|---|
| Naive Bayes | 0.7371 | 0.7488 | 0.7371 | 0.6950 |
| **Logistic Regression** | **0.7759** | **0.7664** | **0.7759** | **0.7637** |

Logistic Regression outperforms Naive Bayes on every metric, most notably on recall for the minority
`Neutral` and `Positive` classes — Naive Bayes is more biased toward predicting the majority `Negative`
class when uncertain.

## Confusion Matrix Results

`Negative` is the easiest class to classify (highest recall) — it is both the majority class and has the
most distinctive vocabulary (`delay`, `cancel`, `hour`, `hold`). `Neutral` is the hardest: a meaningful share
of actual Neutral tweets are misclassified as Negative, since short, factual Neutral tweets share operational
vocabulary (`flight`, `help`, `time`) with genuine complaints, without a distinguishing positive or negative
signal of their own.

## WordCloud Analysis

- **Positive:** dominated by gratitude/praise words — `thank`, `great`, `love`, `good`, `awesome`.
- **Negative:** dominated by operational complaint words — `hour`, `cancel`, `delay`, `wait`, `hold`, `bag`.
- **Neutral:** dominated by transactional/informational words — `need`, `help`, `dm`, `book`, `ticket`,
  `change`, `tomorrow`.

## Error Analysis

Of the 2,910 test-set predictions, 652 (22.41%) were misclassified using the best model (Logistic
Regression). Recurring error patterns, drawn from actual misclassified examples:

- Neutral, factual-sounding tweets containing complaint-adjacent words (e.g. "flight," "cancel") predicted
  as Negative
- Short, mildly positive acknowledgements ("thanks for contacting me") predicted as Neutral
- Implicit-negative tweets phrased as questions, lacking an obviously negative word
- Mixed-sentiment tweets combining a complaint with a compliment
- Very short tweets left with little content after preprocessing

## Key Findings

1. 14,550 tweets analyzed after cleaning
2. 3 sentiment classes (Negative, Neutral, Positive) — natively present in the dataset
3. Class distribution: Negative 62.86% · Neutral 21.00% · Positive 16.14%
4. Best-performing model: **Logistic Regression**
5. Best weighted F1-score: **0.7637**
6. Most common error: Neutral tweets misclassified as Negative
7. Distinctive vocabulary identified per class (see WordCloud Analysis above)
8. Business value: automated, scalable sentiment triage — strong enough for bulk categorisation and trend
   tracking, not intended as the sole basis for high-stakes individual decisions given the ~22% error rate

## Real-World Applications

Customer feedback triage, social media monitoring, product/service issue analysis (e.g. routing complaints
by category — delays vs. baggage vs. hold times), customer support escalation prioritisation, and
brand/competitor sentiment tracking over time.

## Limitations

- Significant class imbalance (Negative ≈ 4x Positive), which limits how much distinguishing vocabulary the
  model can learn for the minority classes
- Sarcasm and implied sentiment are a fundamental blind spot for TF-IDF + linear models
- scikit-learn's stopword list can remove some negation-adjacent words, blunting negation handling
- Short tweet length leaves limited content after cleaning
- TF-IDF has no real semantic understanding — no synonym recognition, limited context beyond bigrams
- Trained on a single domain (US airlines) and time period (February 2015); would need re-evaluation before
  use elsewhere
- Positive class has the fewest training examples (~1,878) of the three

## Conclusion

Raw, noisy tweet text was cleaned and converted into TF-IDF numerical features without any test-set leakage,
then used to train and fairly compare two classical classifiers. Logistic Regression was the clear
best-performing model on every metric. The resulting pipeline correctly classifies roughly 78% of tweets and
is well suited to bulk sentiment triage and trend monitoring, while the documented error analysis makes clear
where — sarcasm, implicit sentiment, mixed messages — this class of model genuinely struggles.
